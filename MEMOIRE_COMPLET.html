1. Introduction Générale

La gestion des ressources documentaires dans les institutions académiques et culturelles est une activité critique qui nécessite une organisation méthodique et une traçabilité complète. Les bibliothèques modernes font face à des défis importants : cataloguage de milliers de documents, gestion des emprunts, suivi des lecteurs, production de statistiques, et optimisation de l'accès aux ressources.

Ce mémoire présente le développement d'une solution logicielle complète destinée à moderniser et automatiser la gestion des bibliothèques. Le projet Bibliothèque UAC est une application web et desktop développée avec les technologies les plus récentes et les meilleures pratiques du génie logiciel.

L'objectif principal est de fournir un système intégré, intuitif et performant capable de répondre à tous les besoins opérationnels d'une bibliothèque contemporaine, tout en assurant la sécurité des données et l'efficacité des processus.

2. Contexte et Problématique

2.1 Situation Actuelle

Actuellement, de nombreuses bibliothèques, notamment celle de l'Université Assane Seck de Kaolack (UAC), gèrent encore leurs ressources documentaires de manière partiellement manuelle ou avec des systèmes obsolètes. Cette approche crée plusieurs problèmes :

  • Manque de traçabilité complète des emprunts et retours
  • Difficulté à localiser rapidement un document dans la collection
  • Absence de statistiques réelles sur l'utilisation des ressources
  • Processus d'emprunt laborieux et fastidieux
  • Risque accru de perte ou de détérioration de documents
  • Absence de communication automatisée sur les retards

6.3 Authentification et Sécurité

Flux d'Authentification

  1. L'utilisateur accède à la page de login
  2. Il saisit son nom d'utilisateur et mot de passe
  3. Le backend vérifie les identifiants dans la base de données
  4. Si valides, un token JWT est généré et renvoyé
  5. Le token est stocké dans le localStorage du navigateur
  6. Chaque requête API inclut le token dans l'en-tête Authorization
  7. Le backend vérifie le token avant d'exécuter la requête

Points de Sécurité Implémentés

  • Mots de passe hashés avec bcrypt (10 rounds)
  • Tokens JWT avec expiration (8 heures)
  • Validation des entrées côté serveur
  • HTTPS recommandé en production
  • Contrôle d'accès basé sur les rôles (Admin, Bibliothécaire)
  • Protection contre les requêtes CSRF

8.3 Architecture technique et API

L'application est construite suivant une architecture "full-stack" classique : un backend Node.js / Express (REST API sécurisée) et un frontend React (SPA) consommant ces APIs.

8.3.1 Backend (Node.js + Express + Sequelize)

Le backend se situe dans backend/src et s'appuie sur les composants suivants :

  • app.js : point d'entrée, configuration d'Express, middlewares globaux (CORS, JSON parsing, logging, etc.)
  • routes/ : définition des routes par domaine (`auth.js`, `books.js`, `loans.js`, `consultations.js`, `stats.js`, `alerts.js`, `activities.js`, etc.)
  • controllers/ : logique métier et traitement des requêtes (authController, bookController, statsController, etc.)
  • models/ : définition des entités (User, Book, Loan, Consultation, Reader, Activity) via Sequelize et configuration des relations.
  • config/db.js : configuration de la connexion Sequelize à la base MySQL/MariaDB.
  • middleware/ : middlewares réutilisables (`auth.js` pour JWT + RBAC, etc.).
  • utils/ : utilitaires (logActivity, seed, reset_db, etc.).

Fonctions clés du backend

  • authController : gestion de la connexion (JWT), inscription (directeur + lecteur), liste et suppression d'utilisateurs.
  • bookController : CRUD livres, gestion du stock (exemplaires disponibles).
  • loanController : emprunts, retours, marquage retards, mise à jour du stock.
  • consultationController : enregistrement des consultations, calcul d’heures, détection des plus de 2h.
  • statsController : calculs statistiques, tendances, répartition par filière/faculté, exports (PDF/Excel) et données pour les graphiques.
  • alertController : génération des listes d’alertes (stocks vides, retards, consultations prolongées).
  • activityController : récupération des logs d’activité pour la surveillance et l’audit.

Gestion des rôles et sécurité

Le système supporte plusieurs rôles : directeur, bibliothecaire et lecteur. Le rôle est stocké dans la table users et est inséré dans le token JWT.

Protection des routes :

  • Token JWT : envoyé dans l'en-tête Authorization: Bearer <token> (géré par axios dans le frontend).
  • authenticateToken : middleware qui vérifie et décode le token JWT.
  • requireRole : middleware qui vérifie que le rôle de l'utilisateur correspond aux autorisations attendues pour certaines routes (ex. création d'utilisateur, suppression, accès admin, etc.).

8.3.2 Frontend (React + Tailwind + Recharts)

Le frontend est organisé en composants et pages, avec un routage role-based : /librarian pour le bibliothécaire, /admin pour le directeur.

Composants principaux :

  • Pages : Login.jsx, Librarian.jsx, Admin.jsx, Books.jsx, etc.
  • Panneaux : BooksPanel.jsx, LoansPanel.jsx, AlertsPanel.jsx, StatsPanel.jsx, SettingsPanel.jsx, etc.
  • Composants partagés : ExportButton.jsx, Header.jsx, Sidebar.

Gestion de l'état :

  • Les données sont chargées via des useEffect synchronisés avec les filtres (période, dates, etc.).
  • Le token JWT est stocké dans localStorage et appliqué automatiquement aux requêtes via un interceptor Axios.
  • Les préférences (langue, thème) sont également stockées dans localStorage pour persistance.

Gestion Multilingue

La bibliothèque react-i18next est utilisée pour fournir des traductions (fr/en/es). Les fichiers de traduction sont définis dans src/i18n.js et plusieurs composants utilisent la fonction t() pour afficher les textes.

Gestion du thème

Le thème clair/sombre est géré via une classe dark ajoutée à la racine (document.documentElement), et les styles Tailwind réagissent à cette classe. Le choix est enregistré dans localStorage pour persistance.

8.3.3 Modules clés et flux

1. Connexion

  • L'utilisateur saisit ses identifiants dans Login.jsx.
  • Le formulaire appelle POST /api/auth/login et reçoit un token + infos utilisateur.
  • Le token est stocké dans localStorage et Axios envoie ce token dans l'en-tête pour chaque requête suivante.
  • Le rôle (directeur/bibliothécaire/lecteur) détermine la route d'accès (admin/librarian/books).

2. Export PDF / Excel

L'application propose plusieurs exports :

  • Alertes : génération PDF à partir des données renvoyées par les endpoints d'alerte.
  • Statistiques : génération PDF (via StatsPanel) et Excel (via xlsx) à partir des datasets statistiques.

Le composant ExportButton encapsule la logique d'appel API et de génération du fichier. Pour les PDF, il utilise jspdf et jspdf-autotable, en adaptant l'orientation, les marges et les styles pour garantir la lisibilité.

3. Journalisation des actions (Audit)

Le backend enregistre automatiquement les actions importantes via utils/activityLogger.js. Chaque entrée contient :

  • utilisateur_id : lien vers le compte ayant effectué l'action
  • action : description courte (ex. "Création utilisateur", "Suppression livre")
  • details : JSON des données (ex. id du livre, modifications, etc.)
  • timestamp : date / heure (automatique en base)

Le frontend affiche ces logs dans le panneau Activités, en convertissant automatiquement les ID vers des noms lisibles (ex. remplace livre_id par le titre du livre).

12.3 API Endpoints Principaux

Authentification

POST /api/auth/login - Connexion POST /api/auth/register - Créer utilisateur GET /api/auth/users - Lister utilisateurs DELETE /api/auth/users/:id - Supprimer utilisateur

Livres

GET /api/books - Lister tous les livres POST /api/books - Créer un livre GET /api/books/:id - Détail d'un livre PUT /api/books/:id - Modifier un livre DELETE /api/books/:id - Supprimer un livre

Emprunts

GET /api/loans - Lister emprunts POST /api/loans - Créer emprunt PUT /api/loans/:id/return - Enregistrer retour GET /api/loans/late - Lister emprunts en retard

Lecteurs

GET /api/readers - Lister lecteurs POST /api/readers - Créer lecteur GET /api/readers/:id - Détail lecteur PUT /api/readers/:id - Modifier lecteur DELETE /api/readers/:id - Supprimer lecteur

Statistiques

GET /api/stats/summary - Résumé des stats GET /api/stats/loans - Stats emprunts GET /api/stats/consultations - Stats consultations
